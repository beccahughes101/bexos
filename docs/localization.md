# Local localization

Implementation status: the APIs below describe the current working-tree code.
The approved local plan is incomplete; final regression and both QEMU acceptance
runs remain outstanding. See [current gaps](rfcs/0066/CURRENT.md#current-gaps-in-the-approved-local-scope).

RFC 0066 separates application translations from regional formatting. Fluent
sources are compiled by Bazel; applications resolve indexed `strings.bexres`
catalogs without parsing FTL. Native ICU4X providers borrow an immutable mapping
of the shared `cldr.bexloc` VMO served by `localed`.

Production SysUI, UserUI, and Dioxus demo catalogs contain **English only**.
Selecting another display language therefore falls back to English. Multilingual
fixtures under `testing/e2e/qemu/localization` provide German, Russian, and Arabic
translations for live-switching tests; they are not production translations.
Online language packs, pkgd integration, and a settings panel remain future work.
See [RFC 0066 current status](rfcs/0066/CURRENT.md) for validation results.

## Packaging

Place FTL files under canonical locale directories, such as
`locales/en-US/main.ftl`. Declare a bundle and embed its generated bytes in the
application binary; also package it as an asset when the application needs one.

```starlark
load("//build/rules:locale.bzl", "bexos_locale_bundle")

bexos_locale_bundle(
    name = "strings",
    srcs = glob(["locales/**/*.ftl"]),
    default_locale = "en-US",
)
# On the Rust target:
# compile_data = [":strings"],
# rustc_env = {"BEXOS_STRINGS": "$(execpath :strings)"},
# On app_archive: entries includes "data/locale/strings.bexres": ":strings".
```

`fluent-syntax` 0.12.0 supplies the build-time AST. The compiler rejects malformed
FTL, duplicate definitions/attributes, unresolved references, cycles, unsupported
functions, and unsupported function options. The versioned BEXRES artifact has a
hash index, expression and edge tables, and an interned UTF-8 string pool. Runtime
validation bounds table sizes and references. Evaluation bounds depth, steps,
and output; `text()` / `t!` returns `⟪key⟫` on failure, while `resolve()` returns a
typed error for application diagnostics.

```ftl
-brand = BexOS
welcome = Welcome to { -brand }, { $name }!
    .title = Welcome
items = { $count ->
    [one] One item
   *[other] { NUMBER($count) } items
}
modified = { DATETIME($timestamp, dateStyle: "long", hourCycle: "h23") }
```

Attributes use dotted keys (`welcome.title`). Terms can receive named arguments;
message references inherit arguments. Nested selectors accept string keys, exact
decimal values, and CLDR plural categories. `NUMBER` supports minimum/maximum
fraction digits, minimum integer digits, and grouping. `DATETIME` accepts an ISO
civil date/time string or integer Unix epoch milliseconds in UTC, with date/time
styles, calendar, and hour-cycle options. Named time zones are outside this local
implementation. Full dates include weekdays; time precision is minutes for
`short`, seconds otherwise. No timezone names are exported.

The resolver tries each configured language followed by its parents, then the
bundle baseline if not already tried. It searches for matching plural variants
before resorting to Fluent's default variant. Plural rules follow the language of
the translation being evaluated. Number/date/currency/list formatting follows the
independent regional locale, not the translation language.

## Shared formatting data

`//data/locale:base` exports ICU4X 2.2 data using `icu_provider_source`,
`icu_provider_export`, and `icu_provider_blob`. MODULE.bazel pins checksums for
CLDR 48.2 and the ICU 78.1rc export source archive. Only formatting, plural,
calendar, list, and locale-direction markers used by the wrapper are exported;
time-zone names, collation, and segmentation data are omitted. The experimental
currency API is confined to `lib/i18n/formatting/src/currency.rs`.
Currency formatting preserves the supplied decimal precision; pass `"12.00"`
when two fractional digits are required.

The default build includes `en-US`. Additional locale coverage is a build setting:

```sh
bazel build //services/localed:localed_archive \
  --//data/locale:locales=en-US,de-DE,ru,ar
```

A regional locale absent from the blob uses the `en-US` formatting baseline.
Translations for additional languages must be built alongside their plural data;
the compiler does not invent plural rules. The wrapper exposes number, currency,
calendar/date/time, list, plural, direction, and effective formatting-locale APIs.
Measurement and first-weekday preferences are available in `Settings` for widgets;
the wrapper does not convert arbitrary units.

## Preferences and service authority

The prototxt config-only package is `bexos.locale.preferences`. Use the existing
CLI; substitute the generation reported by `get` before each mutation:

```sh
bexctl prefs get bexos.locale.preferences --uid 1000
bexctl prefs set bexos.locale.preferences 0 --uid 1000 \
  language_priority=string:de-DE,en-US override_region=string:en-US \
  measurement_system=string:metric hour_cycle=string:h23 first_day_of_week=u32:1
```

The language string decodes to at most eight distinct canonical BCP 47 tags.
Defaults are `en-US`, US customary measurements (`us`), H12 (`h12`), and Sunday
(`7`; Monday is `1`). An empty `override_region` follows the first display locale.
Region overrides are full locale tags. Measurement values are `metric`, `us`,
and `uk`; hour cycles are `h11`, `h12`, `h23`, and `h24`. All fields support normal
prefsd policy locks and encrypted per-user persistence. Nonzero users must be
unlocked for access.

`localed` starts in wave 6. `LocaleProvider` exposes settings, a duplicate read-only
CLDR VMO, and watch registration with an initial snapshot and generation. Public
requests obtain UID from their authenticated binding. Only appd, UID 0, may use
`LocaleStartup.Resolve(uid)`. Only localed, UID 0, may access prefsd's private
`LocalePreferences` snapshot/watch feed. Mutations continue through existing
prefsd transactions; the feed never publishes a prepared or uncertain commit.
Generations are per-user persisted revisions. Lock/deletion closes user watchers
and clears cached snapshots. Authenticated public bindings can request a new
watch after unlock; requests while locked are rejected once revocation has been
processed. The private feed currently reports lock and deletion only through
watch closure. Retaining public bindings therefore leaves a deletion/UID-reuse
revocation gap: stale bindings are not distinguished from bindings eligible for
unlock recovery. This requires a protocol/lifecycle fix and a live-binding test.
Disconnected listeners are removed; backpressure leaves a pending generation
for retry. Guest-level ordering and revocation acceptance remain unverified.

## Application APIs and ownership

A prototxt application manifest consumes `bexos.locale.LocaleProvider`, capability
`Public`, ordinals 1, 2, and 3. Startup version 10 adds an optional locale
descriptor: VMO, length, data generation, and an encoded settings snapshot.
Receivers still decode startup versions 2–9. Appd omits locale state before the
locale provider is ready, avoiding a startup dependency cycle.

WASM applications use:

```rust
use bexos_dioxus_guest::locale::{self, LocaleContext, t, use_locale};
const STRINGS: &[u8] = include_bytes!(env!("BEXOS_STRINGS"));
// Stored alongside the application's counters, input, scroll, and view IDs:
let mut context: Option<LocaleContext> = None;
let dirty = locale::poll(&mut context, STRINGS)?;
let locale = context.as_ref().unwrap();
let title = t!(locale, "welcome", name = "Ada");
let language = &use_locale(locale).languages[0];
let direction = locale.direction();
```

Poll before producing a document. A successful change replaces settings and
direction as one context generation and marks the document dirty. Keep model
state and stable node/view IDs outside the context. Put `lang`, `dir`, and CSS
`direction` on the root. Stylo inherits direction; Taffy applies it to layout;
Parley receives language and base direction, included in its bounded shaping
cache key. Explicit physical coordinates remain physical coordinates.

The repository uses retained BexOS documents rather than upstream Dioxus signal
hooks. `LocaleContext`, `I18nProvider`, `use_locale(context)`, and `t!(context, ...)`
fit that invalidation model. Formatting objects are short lived and recreated
from the current settings, so there is no stale formatter cache after a change.

Native applications use `bexos_i18n_client::Client` or the shared context adapter
in `bexos_i18n_client::context`. `NativeBackend::from_startup` takes the descriptor
out of `Startup`. The client owns the VMO and subscription; `MappedData` owns a
read-only address-space mapping. Borrowed ICU providers cannot outlive that
mapping. A mapping remains valid independently of closing its original handle.

The additive `bexos:wasm/locale` WIT interface transfers only bounded settings,
formatting arguments/results, and plural/direction results. The trusted runner
retains the VMO and native mapping; CLDR tables never enter application linear
memory. Application catalogs and translation evaluation remain inside the guest.
Hostcalls require an authenticated LocaleProvider grant and reject formatting
during candidate preparation/restore.

Localed checkpoints its original shared VMO, user snapshots, authenticated
clients, subscriptions, and delivered generations. Prefsd checkpoints private
watchers with its existing transaction state. The runner checkpoints its locale
VMO and listener, then recreates mappings after adoption. Shells rebuild their
locale contexts without replacing their view/model state. The demo also retains
its logical view ID, counter, text, and scroll; its older checkpoint shape is
still accepted. The FIDL reload notification is reserved for future supplementary
data; no online reload implementation is claimed.
